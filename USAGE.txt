Linux 原生加解密隔离启动器

桌面配置中心（推荐入口）：
  ./start.sh
  启动时自动检查 Python 3、GTK4/PyGObject、gcc、g++、binutils、sudo、unshare、
  bubblewrap 和 systemd；缺失时在 apt 系统上自动下载并安装，必要时弹出管理员认证。
  安装失败会停止启动，详情见 state/dependency-install.log；依赖齐全时不会访问软件源。
  /dev/fuse 和现有 sudo 授权仍需系统提供，安装软件包不会修改权限策略。
  start.sh 默认后台启动并立即返回，不占用终端；调试时使用 start.sh --foreground。
  关闭按钮隐藏配置窗口到托盘，最小化使用桌面默认行为；后台监控继续运行，托盘双击或菜单可重新打开。
  安装包会安装 com.yangtu.ytconfig.control.desktop 桌面入口；源码开发直接运行 start.sh。

配置中心提供四个页面：
  概览：查看实际监控状态，控制启停，切换新建文件格式，并预览目录状态。
  监控目录：搜索目录，查看来源和实际挂载状态，添加、启停、移除和重试。可配置排除目录和监控文件类型。
  程序权限：按来源筛选规则，本地追加、删除或停用/恢复服务器项；高级编辑和 Windows/Linux 匹配详情默认折叠。
  服务器与策略：分开呈现连接配置、连通性检测、策略同步和当前合并策略；密钥只显示是否配置及来源。

监控状态在概览主卡显示，底部显示最近操作反馈；配置已保存不代表监控已启动或新格式已生效。
程序权限和服务器配置分别点击本页“应用”，不会保存其他页面的草稿。关闭窗口隐藏到托盘并保留草稿。
Ubuntu GNOME 顶部状态栏会显示盾牌托盘图标；左键重新打开窗口，右键菜单可打开或退出。
应用图标位于 assets/hicolor/scalable/apps/，桌面入口使用同一图标。
托盘依赖 Ubuntu 自带的 ubuntu-appindicators 扩展，未启用时界面仍可使用。
后台运行日志位于 state/launcher-ui.log。

自动监控模式（推荐）：
  启动配置中心后自动安装并启用 systemd 用户服务 ytsysconfig-auto.service，
  把支持目录常驻挂载在原路径；概览页可停止或重新启用。
  在“监控目录”页面选择文件夹；增删、启停后自动保存并在后台更新正在运行的监控。
  删除全部目录后服务等待选择目录，重新添加即可恢复；手动停止监控时不会因目录编辑自行启动。
  界面不再提供独立会话启动区或本地应用启动列表。
  登录后自动启动，Zed、IDEA、cat、文件管理器等无需包装器即可透明访问。
  运行状态见 state/auto/status.json，日志见 state/auto/auto.log。
  引擎退出或挂载失败时自动重试，重试间隔从 1 秒逐步增加到最多 60 秒；
  稳定运行 60 秒后重置间隔，主动停止监控会取消重试。恢复后保留最近退出记录。
  恢复期间访问可能失败；IDEA 等程序持有的旧文件句柄需要重新打开。
  命令行控制：
    systemctl --user start ytsysconfig-auto.service
    systemctl --user stop ytsysconfig-auto.service
    systemctl --user status ytsysconfig-auto.service
  自动模式使用保留文件状态的适配组件：已有密文仍解密读写并保持密文，
  已有明文保持明文。概览中的“新建文件格式”切换即保存；等待服务实际确认后才显示“已生效”。
  设置只影响后续新建文件，服务器同步不会覆盖它；停止服务只卸载视图，不会改写文件状态。
  编辑器将原文件改名备份后，已打开句柄保持原读写视图，避免中途读出密文或破坏文件头。
  普通移动保留源文件状态。受信程序用明文临时文件覆盖已有密文目标时，先生成密文副本，
  保留原目标文件头后再替换；已是密文的源文件、目标不存在的移动及交换仍保留源格式。

监控文件范围：
  在“监控目录 → 排除目录”选择监控根目录下的具体文件夹，例如某个项目的 node_modules。
  配置按完整路径匹配，覆盖所选文件夹及其下级目录，同名的其他目录需分别添加。
  默认排除常见依赖、构建、临时、缓存和版本控制元数据目录，例如 node_modules、build、target、dist、tmp、.cache 和 .git。
  默认规则匹配监控根目录下任意层级的完整目录名，可在界面展开清单或关闭。
  优先判断目录排除，命中后整个子树直接按原始字节访问。新建文件使用明文，已有密文以密文显示。
  从排除目录移动文件时，不能直接覆盖监控范围内已有的密文文件。
  在“监控文件类型”填写扩展名，例如 .java, .py, .d.ts，用逗号或空格分隔，不区分大小写。
  列表预填常用源码、脚本和前端扩展名；可以编辑或清空。仅匹配扩展名的文件进入加解密流程，其余文件直接读写原始字节。
  新建加密同时要求类型命中、目录未排除、概览中选择加密、创建程序符合策略。
  如果编辑器先移走原文件，再把未列入白名单的临时文件移动到原路径，普通移动会保留临时文件的明文格式。
  普通明文保持明文，新文件按所选格式创建（默认明文）；监控范围内匹配加密签名的文件进入解密流程，
  并继续核对程序权限、文件规则及密钥。未配置监控的目录不受影响。
  不额外遍历目录；仅对实际访问到的普通文件检查签名，元数据分类缓存仍然生效。

历史引擎优化记录（以下为原引擎机制对照）：
  原版 Linux sgfs 的 is_need_enc（0x40e0e4）逐条匹配进程及文件规则，
  每条候选都调用 syslog（0x40e270）。一次文件操作可产生多条日志，
  日志条数不等于访问文件数。适配版仅移除此处规则匹配日志，保留其他日志。
  属性查询先判断文件类型和大小，目录、符号链接、特殊文件和不足 1024 字节
  的普通文件跳过加密头检查；普通明文读取跳过进程规则匹配。
  原版 getattr 会跟随链接打开目标检查密文，甚至可能错误扣减链接长度；
  适配版保留 lstat 语义，避免加密目标链接报 I/O 错误及 FIFO 属性查询阻塞。
  密文仍按原程序规则及文件头处理，不启用跨进程明文页缓存，也不移除单线程
  限制：原引擎加解密上下文是共享的，直接并发尚未验证。

性能优化（源码 1.0.6）：
  明文优先走普通读写分支，不检查应用兼容规则，不遍历受信程序列表，不加解密。
  需要识别文件状态时，先读取 32 字节签名，仅疑似密文才读取剩余头部。
  从偏移 0 读取明文时复用正常读取的数据识别，避免额外读头；目录、链接及过短
  文件的属性查询不读取文件头。句柄上的提示仅选择快路径，不缓存文件加密状态。
  密文每次仍复核文件头和策略，内存映射/未知格式/不匹配策略的保护保持不变。
  Git 后台任务改为监听索引目录事件，不再每秒逐仓库查询属性；每分钟轻量校验，
  无法注册监听的仓库每 5 秒查询一次。新仓库发现仅扫描两层目录、跳过缓存目录。
  单个后台配置任务以 nice +10、空闲 I/O 优先级运行，不设置额外内存上限；
  失败不影响已挂载文件服务，并延后重试。此限制不降低前台文件服务的调度优先级。
  整个监控目录仍通过 FUSE，明文也有文件系统转发开销，不是零成本直通。

  3 轮本地临时目录测试的中位数（4000 个明文文件，另有 1000 个缓存文件和 8 MiB 顺序读取）：
  属性查询：0.1233s -> 0.0895s；读取：0.3314s -> 0.2142s；写入：0.2825s -> 0.2475s。
  该工作负载的原生 FUSE 进程 CPU 时间：0.46s -> 0.31s，RSS 约 3 MiB。
  RSS/CPU 不含 Python 监控程序、图形界面和其他应用；上述结果不代表所有实际项目。
  128 个密文文件另测：读取 0.02336s -> 0.02340s，写入 0.02032s -> 0.01943s。
  密文读取基本持平；句柄提示可合并读头调用，但每次仍复核实际文件头和权限。
  原始结果：state/performance-optimization.json。

原版机制对照（基于本地固定版本反汇编）：
  Linux xmp_open/xmp_create 记录 fd 状态，xmp_read 在提供文件句柄时调用
  get_value(int)（0x40e5fd）复用。当前适配版为保留文件状态、逐请求核对权限，
  仍重新检查密文头；尚未引入句柄缓存及其失效机制。
  Windows vfsd_fre_win10_AMD64.Sys 在内核注册过滤器，驱动初始化
  0x14005318e/0x140053199 将 FsRtlCopyRead/FsRtlCopyWrite 填入 Fast I/O
  表，多个路径调用 CcFlushCache/CcPurgeCacheSection。它具有内核文件缓存
  协作路径，不能直接移植为 FUSE 的全局明文缓存。尚未完整还原其文件头缓存
  及失效规则。证据见 ../analysis/vfsd_driver.disasm.txt 和对应 .pe.txt。

  性能回归工具（临时目录挂载，不改动真实项目）：
    python3 tests/engine2/benchmark.py --repeat 3
    python3 tests/engine2/benchmark_metadata.py --before /path/to/old-engine
  工作负载和参数见各工具的 --help；密文样本必须是磁盘密文副本，
  不能从正在解密的项目视图直接复制。

配置与策略：
  config/settings.json：本地配置，权限 600，保存目录、应用、程序名和覆盖记录。
  config/remote_policy.json：最近一次成功导入或下载的服务器策略。
  state/effective_config.json：服务器策略与本地配置合并后的有效配置。
  服务器策略采用本地最终覆盖：可逐项删除同步项，也可关闭“应用服务器同步策略”；
  删除记录在后续同步时继续生效，并可通过“恢复已删除的策略项”清除。
  更新失败不会替换上一份成功策略。

界面固定使用服务器策略，自动更新由开关控制。命令行仍支持以下策略来源：
  原生服务器策略（默认）：运行隔离的原生客户端登录服务器，读取密钥
    LinuxJMData.dat、目录策略 sysconfig.dat 和 Linux 程序规则；URL/路径可留空。
    同一登录会话通过原生客户端的只读查询读取 Windows 已配置应用；有设备分配时
    沿用设备策略，未分配时合并服务器已配置的 Windows 应用清单，不改写服务器配置。
    比较时取程序基本名、去扩展名并转小写，用 Linux 名称查询 Windows 名称是否包含它。
    匹配候选来自本机桌面应用、现有应用配置和服务器明确列出的可执行程序名。
    Windows 原始显示名和进程名保留供核对，不执行 Windows 程序。
    “服务器与策略”可展开查看不含密钥的同步内容；“程序权限”可展开 Windows 应用与 Linux 匹配详情。
  HTTP/HTTPS JSON：返回约定字段的 JSON 策略。
  本地 JSON / 原生策略：选择 JSON，或选择 LinuxJMData.dat 并自动读取同目录 sgfs.conf。
  本机策略命令：命令把 JSON 写到 stdout，适合后续接入原厂登录/取策略协议。
  JSON 字段示例见 config/policy.example.json。

目录组织（当前目录可整体搬移，运行代码不依赖外层 analysis）：
  压缩源码：sh packaging/archive-source.sh
  默认生成 ../linux-client-source.tar.gz，也可将输出路径作为第一个参数传入。
  从 Git HEAD 导出已提交源码，不包含未提交修改、本机配置、策略密钥、运行数据或构建产物。
  此操作需要 Git 仓库；目标机器需重新构建并满足下述依赖。
  src/yt_client/ui/：GTK 配置界面与托盘。
  src/yt_client/monitoring/：挂载、授权、用户服务与隔离文件视图。
  src/yt_client/cli/：策略管理、命令行隔离启动与 Git 显示入口。
  src/yt_client/compat/：Git 只读显示转换。
  src/engine2/：原生并发文件引擎、流式转换器及构建代码。
  src/native/：原生策略查询桥接代码。
  tests/engine2/：引擎验证、性能工具和测试探针。
  packaging/：安装包构建、桌面入口模板和授权规则。
  config/：监控目录及当前服务器下发的加密标识、进程规则。
  vendor/：301 算法组件及其 SHA256 清单，原生文件服务已移除。
  state/：运行生成的程序、会话记录、日志、Zed 数据与最新验证结果。
  原生服务器策略优先查找 YT_NATIVE_CLIENT_ROOT、vendor/native-client 或已安装的 /opt/apps 客户端；
  也支持另行提供的外层开发归档中的原生客户端运行目录。

可选的 ../linux-client-archive/ 开发归档不随本仓库提供，历史内容包括：
  verify_global_view.py：本机真实加密源码集成验证。
  inspect_encrypted.py、decrypt_java301.py、probe_cipher.py：文件检查、
    单文件解密和 Windows 原始算法对照工具。
  tests/：算法对照专用 DLL 与 Unicorn 测试依赖。
  research/：原安装包、策略获取工具、早期挂载实验、反汇编和历史验证材料。
  runtime-sessions/：之前的运行会话记录。

后续服务或安装包以 src/、packaging/、assets/、config/、vendor/ 为主体；state/ 是运行
数据。正式分发时应把原生客户端运行目录放入 vendor/native-client；启用监控会安装当前用户的 systemd 服务和桌面自启动项。
构建需要 Python 3、gcc、g++、binutils；运行需要 sudo、unshare 和 /dev/fuse。
config/ 中含本机当前策略，state/ 和外层归档中有日志和样本，均按私有目录保留。
外层归档中的旧实验使用原厂行为，只用于历史研究，不作为正式启动入口。

命令行隔离启动时，会话根目录只重组已启用支持目录、当前所选工作目录、
系统运行目录和用户缓存目录；未配置的同级项目目录不会出现在会话内。
命令行直接启动时，当前工作目录会自动加入本次会话，保证原命令可用。
已有的普通 Zed、终端进程不会自动进入该视图。Zed 使用独立的运行数据目录，
避免把打开请求转交给视图外的旧进程。上述隔离规则仅适用于命令行会话。
启动依赖当前机器已配置的 sudo 权限、私有挂载命名空间和 /dev/fuse。
本地适配版 sgfs 以普通用户身份运行，应用也不会获得 root 身份。
旧的单线程文件引擎及回调补丁构建器已移除。src/engine2/build.py 构建原生并发文件引擎，
仅复用 vendor/cipher301.bin 中经过校验的 301 算法，不再执行原厂文件服务。

监控目录内文件的读写规则按文件头及服务器策略标识判断，不按扩展名自动加密：
  已有密文：应用读取明文；直接覆盖、追加、截断后仍保存为密文。
  已有明文：读取和写入都保持明文。
  新建文件：可配置明文或加密，默认明文，不继承项目中其他文件的状态。
  选择加密后，由受信程序创建 301 密文；未获授权的普通程序创建会被拒绝。
  经可执行文件身份核验的系统 Git 使用原始文件字节，密文暂存、提交、推送与检出均保持密文。
  仅靠 Git 文件名或脚本参数不能获得传输视图；SVN/Hg 仍按普通程序授权访问。
  明文临时文件覆盖已有密文目标：保持目标加密，保留源文件的其他硬链接和已打开句柄。
  普通移动到不存在的新路径：保留源文件原有状态。
  不支持的加密格式或策略不匹配：拒绝写入，保留原数据。

统一文件读写与兼容补丁：
  普通程序依照策略与文件状态处理；系统 Git 经实际可执行文件身份核验后使用原始字节。
  匹配策略的普通程序读取已支持的密文时得到明文，写回后仍为原 301 密文；
  已有明文保持明文，新文件默认明文、可选加密。明文覆盖已有密文目标时保留目标加密。
  内存映射的内核回写使用打开句柄建立时的授权，普通请求仍核对实际调用者。
  新建副本按新建格式和目录排除设置处理。默认明文。

  src/yt_client/compat/ 只提供独立的只读显示转换；原始 Git 传输在文件引擎中实现。
  Git 显示模块在监控启动及索引变化后后台注册本地显示规则，无需每次手工配置。
  密文历史与差异可通过只读显示转换查看，不改变暂存内容和对象；已有明文历史不会自动清理。
  详细功能、命令和限制见 src/yt_client/compat/USAGE.txt，不把核心通用读写测试当作全软件兼容。

命令行隔离视图的系统布局位于 config/global_view_policy.json，以下仅针对监控目录之外的系统和公共路径：
1. 系统程序、配置、服务数据：/usr（包括本机链接到它的 /bin、/sbin、/lib、
   /lib64）、/etc、/boot、/opt、/var、/srv、/snap、/root、/lost+found。
   在隔离视图中绕过加解密，并以只读方式提供。
2. 公共临时和运行资源：/tmp、/var/tmp、/run、/dev（包括 /dev/shm）、
   /proc、/sys。绕过加解密，保留原有访问权限。
3. 用户缓存、配置、凭据、工具安装和公共目录：.cache、.config、.local、
   .ssh、.gnupg、.pki、.npm、.m2、.gradle、.cargo、.rustup、.conda、
   .nvm、.vscode、.zed、.codex、.docker 等，以及 公共、Public。
   完整名单在 JSON 中；保留原有访问权限。不存在的保留目录会提前创建为
   仅当前用户可访问，确保以后写入也不会触发加密。
4. 自定义 TMPDIR、XDG_RUNTIME_DIR、XDG_CACHE_HOME、XDG_CONFIG_HOME、
   XDG_DATA_HOME、XDG_STATE_HOME 的绝对路径同样绕过加解密。

普通的 /mnt、/media 或 home 下未启用项目目录不会进入受限会话；需要访问时
在“监控目录”页面添加，或从该目录直接执行命令行启动器。
指向被排除目录的符号链接按实际目标保护。

1.0.7 运行布局：
安装版从 /usr/lib/shit-encryption/vendor 执行引擎并加载其 lib 目录中的动态库，启动前校验安装资源。
/run/shit-encryption/<UID> 只保存临时策略、状态、日志和挂载数据，可保持 noexec。
程序路径与策略路径独立传参；安装版不编译、不向运行目录复制程序。
