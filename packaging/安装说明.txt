shit加密 1.0.18 安装说明

系统：x86_64 / amd64，Ubuntu 24.04 及更新版本的桌面环境。
需要 GTK 4.10 以上、systemd 用户会话、/dev/fuse 和允许 bubblewrap 的用户命名空间。
包内携带新引擎所需的 FUSE 库，不替换系统 FUSE。支持内核直通时自动启用。
此包不能安装在 ARM、Ubuntu 22.04 或 Windows 上。

安装（需要联网下载系统依赖）：
  sudo apt install ./shit-encryption_1.0.18_amd64.deb

从应用列表打开“shit加密”。首次使用：
1. 在“服务器与策略”填写服务器地址，先点“应用配置”，再点“立即同步”。
2. 客户端登录后会取得服务器密钥和应用策略；在“监控目录”添加本机文件夹。
3. 启动自动监控；首次按系统提示输入管理员密码；授权持久保存在系统中，以后无需再次输入。
4. 按需打开概览中的“登录后自动启动监控”。重新登录、锁屏和休眠恢复后，启动监控无需再次授权。

监控配置中启用且存在的目录，不要求目录归本人所有，也不额外要求目录可写。
支持 /data 等已有数据盘挂载点；文件实际访问遵循系统权限，不存在或无法挂载的目录记录原因。
自动监控需要内核 /dev/fuse；服务器需可达并允许这台设备接入。
包内不含任何现有设备身份、密钥、服务器地址、策略缓存或个人目录。
编译好的加密引擎和原生策略客户端已包含，用户不需要 GCC/G++。
依赖由 APT 安装；这不是离线全依赖安装包。

配置：~/.config/shit-encryption/
同步缓存与日志：~/.local/state/shit-encryption/
引擎与动态库：/usr/lib/shit-encryption/vendor/，由安装包管理，不复制到运行目录。
监控状态与临时策略：/run/shit-encryption/<用户UID>/，支持 /run 挂载为 noexec。
无需修改 /run 的挂载选项，也无需安装开机 remount 服务。

本安装包为 1.0.18，使用 C++ 并发文件引擎。
开发启动方式：linux-client/start.sh；核心统一按策略与原文件状态处理，src/yt_client/compat/ 仅提供只读显示转换。
已加密文件在匹配程序中按明文读写，落盘保持原 301 格式；明文文件保持明文。
概览中的“新建文件格式”可选明文或加密，切换即保存；以监控确认的“已生效”状态为准，未启动时显示待启用。
此设置仅影响后续新建文件，服务器同步不会覆盖；明文临时文件覆盖已有密文目标时保持目标加密。
普通移动到不存在的路径、已是密文的源文件和交换仍保留源格式；未授权程序不能创建加密文件。
系统 Git 按受保护的可执行文件身份核验，暂存、提交、推送和检出均保持文件原始字节：明文仍是明文，密文仍是密文。
仅靠程序名称或脚本参数不能获得传输视图；差异与历史由只读显示转换查看。
SVN/Hg 仍按普通授权规则访问。本次升级不自动加密已有明文，也不改写已泄露的历史。
监控未运行时不会自动加密；该配置不是提交时加密开关，也不会批量转换已有文件。
监控仅使用配置目录，不设置系统路径黑名单；实际访问遵循请求者 UID、主组和附加组权限。
停止监控后卸载：
  sudo apt remove shit-encryption
用户配置保留，不自动删除密钥、缓存或用户数据。

1.0.18：“终端授权”固定显示在概览的监控操作区。监控已运行或未同步密钥时，按钮仍可见但不可点击。

1.0.17：如果桌面密码框未出现，在概览点击“终端授权”。终端优先使用系统 sudo 认证；未安装 sudo 时使用 Polkit。
授权通过后自动请求启动监控。如果界面无法打开终端，在本机终端以当前普通用户运行：
  /usr/bin/python3 /usr/lib/shit-encryption/src/yt_client/monitoring/auto_mount.py --authorize-in-terminal

1.0.16：首次启用监控时，由桌面程序向 Polkit 发起管理员授权，验证成功后再启动后台服务。
如果桌面缺少 Polkit 认证代理，可在本机终端执行 pkexec /usr/lib/shit-encryption/mount-broker --authorize-only。
启动与状态查询清理继承的 LD_PRELOAD、LD_LIBRARY_PATH 和 LD_AUDIT，避免第三方程序的加载器警告干扰。

1.0.15：写入加密文件的明文视图时，若输入会形成内嵌密文头，引擎返回 EBADMSG，避免重复加密。
分段写入也会检查。失败的复制可能留下空目标或已写入片段。

1.0.14：在“监控目录”中加入排除目录和监控文件类型。默认排除 node_modules、build、target、dist、tmp 等常见目录，预填常用源码、脚本和前端扩展名。
排除目录优先，整个子树按原始字节访问。其余路径只处理扩展名列表中的文件；清空列表后不监控任何类型。
新建文件需同时命中类型、位于排除目录外、启用加密新建且由受信程序创建，才会加密。
排除范围内的已有密文按密文访问。从排除目录移动文件时，不能直接覆盖监控范围内的已有密文。

1.0.13：修复受信 Git 暂存解密视图导致推送明文的问题；即使策略通配信任 Git，也使用原始字节传输。
修复明文临时文件覆盖已有密文目标时的格式降级；加密新建模式下 Git 自身元数据仍保存为可用格式。
真实仓库的历史和远端不会被安装程序修改，历史中已存在的明文需另行评估处置。
同版本更新为概览、监控目录、程序权限、服务器与策略四页深色界面。目录支持搜索、来源与挂载状态；程序规则支持来源筛选、本地追加与服务器项本地停用/恢复。
程序权限与服务器配置独立应用，其他页面的草稿不会被顺带保存；同步期间已保存的本地修改会保留。监控启动、实际挂载、配置生效和策略同步分别反馈。
修复 X11 桌面托盘唤出后窗口仍被其他应用遮挡的问题：无点击时间戳时获取有效服务端时间，不设置永久置顶。
Wayland 使用桌面提供的激活令牌；未提供有效令牌时，桌面可能限制后台窗口置前。

1.0.12：修复修改新建文件格式触发重启后，已有授权记录被重复创建，导致服务持续退出的问题。
旧版在部分系统 umask 下会创建可组写的授权父目录，之后安全校验拒绝该记录。
管理员授权启动时修复 root 所有的授权目录和普通记录权限，保留记录，不跟随符号链接或改写其他文件。
升级后重新打开客户端并启动监控；如系统要求管理员授权，请完成一次授权。
服务失败时界面显示退出原因及 journalctl 查询命令；正常停止不显示旧的失败记录。

1.0.11：首次授权 root 所有的固定挂载助手后，后续启动和异常恢复无需重复输入系统密码。
授权记录位于 /var/lib/shit-encryption/authorized-users/<用户UID>，仅 root 可修改；
管理员可删除对应记录撤销授权，不影响策略对应用解密权限的控制。
用户服务异常退出后自动重启；策略内容未改变时不再重启监控。
修复目录读取回复与关闭并发时，解锁已释放互斥锁导致文件句柄内存损坏的问题。
自动恢复无法修复应用持有的旧文件句柄，恢复后需要重新打开文件。

1.0.10：移除监控用户 UID、系统目录黑名单、程序名称与编辑器文件名的特殊限制。
按请求处理 UID、主组和附加组，容器用户可按系统权限读取绑定配置。
重命名采用系统语义，支持跨目录、硬链接与交换；保留源文件格式和元数据。

1.0.9：修复编辑器将原文件改名备份后，已打开句柄切换成密文视图的问题，
避免后续写入破坏文件头。所有编辑器临时文件按新建格式设置创建，替换时保留源文件格式。
重命名不再读取文件内容，命名管道也按系统语义处理。
配置监控目录后，全部子目录和文件参与检查，不按目录名、文件名或扩展名排除。
旧配置中的 file_scope 排除规则不再生效，界面已移除排除设置。
增加新建文件格式设置，可选明文/加密，默认明文。
引擎退出和挂载失败自动重试，间隔从 1 秒逐步增加至最多 60 秒；
稳定运行 60 秒后重置间隔，主动停止监控会取消重试。
引擎恢复后，应用持有的旧文件句柄需要重新打开。

1.0.8：回收不活跃文件节点的描述符缓存，避免大目录扫描持续占用句柄；
停止监控时通过受控通道卸载，避免残留 root 监控进程。异常退出原因写入监控状态和日志。
异常日志：界面顶部“查看日志”可直接打开日志文件夹。
仅记录异常，正常监控、扫描和文件读写不写日志；同类错误每分钟最多记录一次。
每个日志文件最大 1 MiB，保留 3 份轮转备份。日志不记录文件内容和策略密钥。
用户日志位于 ~/.local/state/shit-encryption/logs/；其中 monitor 入口指向
/var/log/shit-encryption/<用户UID>/，保存监控及引擎异常，重启后仍保留。
