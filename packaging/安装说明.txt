shit加密 1.0.11 安装说明

系统：x86_64 / amd64，Ubuntu 24.04 及更新版本的桌面环境。
需要 GTK 4.10 以上、systemd 用户会话、/dev/fuse 和允许 bubblewrap 的用户命名空间。
包内携带新引擎所需的 FUSE 库，不替换系统 FUSE。支持内核直通时自动启用。
此包不能安装在 ARM、Ubuntu 22.04 或 Windows 上。

安装（需要联网下载系统依赖）：
  sudo apt install ./shit-encryption_1.0.11_amd64.deb

从应用列表打开“shit加密”。首次使用：
1. 在“服务器与策略”填写服务器地址，点击同步按钮。
2. 客户端登录后会自动取得服务器当前加密密钥和应用策略；添加需要监控的本机目录。
3. 启动自动监控；首次按系统提示输入管理员密码；授权持久保存在系统中，以后无需再次输入。
4. 按需打开“开机启动”。重新登录、锁屏和休眠恢复后，启动监控无需再次授权。

监控配置中启用且存在的目录，不要求目录归本人所有，也不额外要求目录可写。
支持 /data 等已有数据盘挂载点；文件实际访问遵循系统权限，不存在或无法挂载的目录记录原因。
自动监控需要内核 /dev/fuse；服务器需可达并允许这台设备接入。
包内不含任何现有设备身份、密钥、服务器地址、策略缓存或个人目录。
编译好的加密引擎和原生策略客户端已包含，用户不需要 GCC/G++。
依赖由 APT 安装；这不是离线全依赖安装包。

配置：~/.config/shit-encryption/
同步缓存与日志：~/.local/state/shit-encryption/
引擎与动态库：/usr/lib/shit-encryption/vendor/，由安装包管理，不复制到运行目录。
监控状态与临时策略：/run/shit-encryption/<用户UID>/，支持 /run 挂载为 noexec。
无需修改 /run 的挂载选项，也无需安装开机 remount 服务。

本安装包为 1.0.11，使用新的 C++ 并发文件引擎；旧文件引擎已移除。
开发启动方式：linux-client/start.sh；核心统一按策略与原文件状态处理，compat/ 仅提供只读显示转换。
已加密文件在匹配程序中按明文读写，落盘保持原 301 格式；明文文件保持明文。
概览中的“新建文件保存格式”可选明文或加密，默认明文；选择后点击“应用”。
此设置仅影响后续新建文件，服务器同步不会覆盖；重命名和替换保留源文件自身格式。
加密模式下，未获授权的程序不能创建文件；Git/SVN/Hg 不再有名称豁免。
受信版本控制程序读取明文，提交内容也可能是明文。已有密文历史可用独立只读转换显示。
监控仅使用配置目录，不设置系统路径黑名单；实际访问遵循请求者 UID、主组和附加组权限。
停止监控后卸载：
  sudo apt remove shit-encryption
用户配置保留，不自动删除密钥、缓存或用户数据。

1.0.11：首次授权 root 所有的固定挂载助手后，后续启动和异常恢复无需重复输入系统密码。
授权记录位于 /var/lib/shit-encryption/authorized-users/<用户UID>，仅 root 可修改；
管理员可删除对应记录撤销授权，不影响策略对应用解密权限的控制。
用户服务异常退出后自动重启；策略内容未改变时不再重启监控。
修复目录读取回复与关闭并发时，解锁已释放互斥锁导致文件句柄内存损坏的问题。
自动恢复无法修复应用持有的旧文件句柄，恢复后需要重新打开文件。

1.0.10：移除监控用户 UID、系统目录黑名单、程序名称与编辑器文件名的特殊限制。
按请求处理 UID、主组和附加组，容器用户可按系统权限读取绑定配置。
重命名采用系统语义，支持跨目录、硬链接与交换；保留源文件格式和元数据。

1.0.9：修复编辑器将原文件改名备份后，已打开句柄切换成密文视图的问题，
避免后续写入破坏文件头。所有编辑器临时文件按新建格式设置创建，替换时保留源文件格式。
重命名不再读取文件内容，命名管道也按系统语义处理。
配置监控目录后，全部子目录和文件参与检查，不按目录名、文件名或扩展名排除。
旧配置中的 file_scope 排除规则不再生效，界面已移除排除设置。
增加新建文件格式设置，可选明文/加密，默认明文。
引擎退出和挂载失败自动重试，间隔从 1 秒逐步增加至最多 60 秒；
稳定运行 60 秒后重置间隔，主动停止监控会取消重试。
引擎恢复后，应用持有的旧文件句柄需要重新打开。

1.0.8：回收不活跃文件节点的描述符缓存，避免大目录扫描持续占用句柄；
停止监控时通过受控通道卸载，避免残留 root 监控进程。异常退出原因写入监控状态和日志。
异常日志：界面顶部“打开日志目录”可直接打开日志文件夹。
仅记录异常，正常监控、扫描和文件读写不写日志；同类错误每分钟最多记录一次。
每个日志文件最大 1 MiB，保留 3 份轮转备份。日志不记录文件内容和策略密钥。
用户日志位于 ~/.local/state/shit-encryption/logs/；其中 monitor 入口指向
/var/log/shit-encryption/<用户UID>/，保存监控及引擎异常，重启后仍保留。
